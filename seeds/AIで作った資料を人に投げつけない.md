# AIで作った資料を人に投げつけない（仮）

## ワンメッセージ

AI で作った長い資料が相手に伝わらないのは、「絞れていない」から。
（言い切れるのは、ロジックツリーで特定した課題の場所まで。絞り方は一例として提案する）

## 元の問題意識（音声入力そのまま）

- AI が作った資料は、めちゃくちゃ長い。長くて、相手に負担をかけている
- AI に書かせた Notion や MD ファイルを、仕事で人に投げつける。あれは仕事じゃなくて、良くないこと。相手に負担をかけている
- AI と議論して壁打ちして、詰めていくこと自体は全く問題ではない
- 問題は「他者に伝える」とき
  - 伝えられる他者は、AI との壁打ちの背景も、そのときのディテール（詳細な段階）も知らない
  - その状態で、一気に大量の資料を読まされる
  - その資料に「まず結論は何なの」「それを補完する論点は何か」「それを補足する理由は何か」がない
  - ピラミッドストラクチャーのような構造がないと、本当に何を言っているか分からなくて、読むのが辛い
- 俺はこれを失敗してやっちゃった。その失敗談をケースに、人に伝えられる形にする話を書きたい

## 流れのイメージ（音声入力から）

1. AI で作った資料（記事じゃなくて資料）って、めちゃくちゃ長いよね。相手に負担をかけてるよね
2. 何が問題なのかを出す
3. 結局どうすればいいの？ となるので、ピラミッドストラクチャーみたいな人間が理解しやすい形に落とし込んで伝えることが大事、というところに落とし込む
4. 自分の失敗談をケースにして、そこから「人に伝える」話にする

## 決まっていること

- 記事は短くてよい（2,000〜3,000字くらい）
- 順番：最初に「何が問題か」→「じゃあどうすればいいか」を端的に伝える → そのあとに事例として自分の失敗談で具体を見せる
  - 結論を先に言う構造そのものが、記事の主張（ピラミッドで渡す）の実践になる

## 記事の骨子（筆者が口頭で語ったイメージ）

- 世の中にはびこっている、AI に作らせたダラダラ長い資料。これは他者に読ませるためのものではない。それは仕事ではない
- 他者に伝えるときに大事なのは、まず「伝わること」
- AI に作らせた長い資料は、相手に読んでもらえない。読んでもらえても、相手にとって負荷になる。その負荷を相手に与えたいですか？ 与えたくないなら、ちゃんと考えましょう
- 相手が読むのに負荷がある（読みたくない）資料を出すと、自分の目的の達成も難しくなる
- そうならないために、ちゃんと考えて資料を作って伝える
  - 結論から話す → 背景を伝える → もう一度結論 → 補足する理由を端的に3つくらい
  - 理由は相手の関心に絞る
- エンジニアは具体に入るとき、あらゆることを考慮して考える。それは実現フェーズではとても重要
- でも伝えるときは、相手に判断してほしい・アクションを取ってほしいケースが多い。それに必要な情報にフォーカスして伝える
- ピラミッドストラクチャーは「参考になるのは」くらいの一言。何度も言わない

## ロジックツリー（課題の特定）

```
AIで作った長い資料は、相手に伝わらない
├── 読まれない
│     └ なぜ:量が多くて、読む負荷が高い
│        ・パッと見て「AIの資料ね、よく分からん」となる
│        ・長くて、読むのが辛い
├── 分からない
│     └ なぜ:AIが出した膨大な情報が、絞られていない
│        ・書き手がどの論点で考えて、何を伝えようとしているのかが見えない
└── 判断できない
      └ なぜ:判断には「相手の関心」が必要なのに、そこに合った情報がない
         ・関心に合った情報が、資料の中に埋もれている（または無い）
```

- 根っこは一つ：3つとも「絞れていない」。違うのは絞る基準（量そのもの / 書き手の論点 / 読み手の関心）
- 「分からない」＝書き手の問いが見えない、「判断できない」＝読み手の問いに答えていない
- 解決の核：書き手の論点を、読み手の関心に合わせて決めて、それに絞る。ピラミッドは、その結果を並べる型
- ロジックツリーは記事中にコードブロックで載せる（mermaid は Zenn で見にくい、画像は使わない）。詳細版のまま載せる

## 骨組み（確定）

```
## はじめに
  AIで作った長い資料は、相手に伝わらない。根っこは「絞れていない」こと。
  一つのやり方として、相手の関心から問いを決めて、そこに絞って伝えてみよう（2〜3行）

## AIで作った長い資料、よく見かけませんか
  - 壁打ち自体は問題ない。問題は、それをそのまま他者に渡すこと
  - あるある：カラフルなのに「で、結局何が言いたいの？」
  - 自分もやってしまった（1〜2文。強調しない）

## なぜ伝わらないのか
  （ロジックツリー：詳細版をコードブロックで）
  読まれない / 分からない / 判断できない → 根っこは「絞れていない」

## どう絞るか（一例）
### 相手の関心から、答えるべき問いを決める   ← 判断できない への手当て
### 問いへの答え（結論）を先に置く           ← 分からない への手当て
### 背景と理由は、判断に必要な分だけ        ← 読まれない への手当て
  - 型としてはピラミッドストラクチャー（ここで名前を出す）
  - 壁打ち用の資料と、伝える資料は分ける
  - この記事も、同じ形で書いている
```

- 記事の本質は「なぜ伝わらないか（課題の特定）」と「どう絞るか（How）」
- 言い切るのは課題の場所（根っこは絞れていない）まで。ロジックツリーで示せる範囲
- 「どう絞るか」はただの一例。「僕はこうしている」くらいの温度で出す（断定しない）
- ピラミッドストラクチャーは How の中の「型」。結論にもタイトルにも入れない
- ツリーの3つの枝と、How の3ステップが1対1で対応する
- 背景では「世の中の課題であり、自分もやってしまった」程度。失敗談は強調しない

### 経緯メモ（採用しなかった案）

- 「結論 / 背景 / 理由」の型に記事を当てはめる案 → ツリーの枝を「理由」にすると How の居場所がなくなるので不採用
- 結論の見出しにピラミッドを入れる案 → ピラミッドは How なので不採用
- 関係：相手の関心 → 相手にとっての問い（イシュー）→ その問いへの答えをピラミッドで。問いが決まらないと結論も決まらない
- 壁打ちの資料に結論が見えないのは、自分が考えていた問いと、相手が知りたい問いが別物だから（仮説）

## 失敗談（詳細は書けない。何が問題か分かるところまで）

1. PdM チャレンジのとき、AI と壁打ちした資料を PO やデザイナーに渡してしまった
2. SRE さんにインフラ相談をしたとき、同じく AI と壁打ちした資料を渡してしまった

共通
- AI + Notion で、いろんな項目の考えが書かれた資料
- 自分は AI と壁打ちすると、あらゆることを考える必要があって、膨大な壁打ちの詳細があった
- 確かにどれも考慮した方がよさそうな、重要そうな内容だった

## 方針（すり合わせ済み）

- ピラミッドストラクチャーは How の中の型として紹介する。結論やタイトルにはしない
- 大事なのは「伝える」を意識すること。相手の関心を考えて、重要な情報に絞る
- 「3つ」と決めているわけではない。人間が理解できるのは3点くらいまで、という感覚
- 資料は2種類に分ける
  - 自分と AI 向けの資料（壁打ちの成果物。詳細でよい）
  - 誰かに伝える資料（誰かを明確に、ペルソナをイメージして、関心を決めてから絞る）
- 伝える相手が1人とは限らない。複数人・複数箇所に向けたメッセージのことも多い。それでも「相手が誰か」を考えるのは重要
- 伝え方の流れ：相手の関心 → 絞る → 背景を共有 → 結論 → 理由の補足
  - 結論先で決定（結論 → 背景 → もう一度結論 → 理由3点くらい）

## 失敗後の反応・今の考え

- 反応は基本的に「後で読んでおきますね」。または「ちゃんと読まないといけない」と思って、めちゃくちゃ大変だったという反応
- 申し訳ないと思って、ちゃんと謝った
- もうやらないようにしようと思って、今はこう考えている、で締める
- メインの失敗談は PO・デザイナーへの話。SRE さんの話は例の1つとして短く

## 伝えるときに考えること（音声入力から。番号は整理用）

人に伝えるには何が重要か → 「伝わること」「判断可能なこと」「目的達成に近づけること」
詳細な具体情報をダラダラ書いた資料は、それに適しているのか？

1. 背景は共有できているか？
   - 自分の中では解像度が高まっていても、伝えられる人は何も知らない。ちゃんと伝えたか？
2. 膨大な分量で、重要なことに絞れているか？
   - AI とのやりとりで「で、何が言いたいの？」となることはないか。大量の文章が返ってきたけど結論は何？ となるあれを、自分でもやってしまっていないか
3. 相手の関心は何か？
   - 相手が判断するときに重要だと思う関心はどこにありそうか
   - デザイナー、エンジニア、PO、事業責任者、顧客…ステークホルダーごとに関心は違う
   - あれもこれも詰め込まれた文章を渡すと、どこを読めばいいか分からない

まとめ
- 人間は大量の文章を読むこと自体が負荷
- だから、読みやすい形式で、関心に合わせた重要な内容に絞って伝える必要がある
